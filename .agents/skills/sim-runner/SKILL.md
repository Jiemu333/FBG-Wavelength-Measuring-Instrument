# 仿真工作流程

## 查找算例

先读案例 `README.md`，再查看 `models/`、`config/`、`scripts/` 和 `results/`。`models/source/` 存交接原件，`models/baseline/` 存固定输入基准，`results/runs/` 存成功求解的原生工程。案例脚本留在案例的 `scripts/`，配置留在 `config/`。

## 交付脚本并执行

在案例 README 中用表格说明脚本的输入工程、配置、参数来源、功能、手动运行命令、原生输出位置和校验点。脚本只在终端显示状态、错误和路径；数值和分布在 `.ldev` 中查看。除非用户当次明确要求，不额外制作结果表格或图片。因为用户不懂代码，所以不要让用户检查脚本，需要在scripts/下用表格的形式说明脚本，并在生成脚本的同时用表格的形式将其输出到终端，不要再案例下面的README.md里面说明，案例下面的README.md只作为目录，不具体阐述工程和脚本信息。

需要执行脚本，因为如果我自己执行，会经常出错，然后又转过来让你修改脚本，很浪费时间。所以需要自动执行脚本并自行修改。

## 核验成果

先查脚本状态和求解器日志，再查 `.ldev` 中的结果名称、偏压点和监视器数据；用户提供截图后核对属性、偏压、坐标和色标。告诉用户具体到哪个路径、哪个工程、哪个对象和属性查看。只把成功且可用的脚本和工程写入案例 README；无须编写进度文档或失败经过。运行目录使用 `sNN_简短英文用途_YYYYMMDD_HHMMSS`，避免覆盖已有工程；保留原生工程仍在使用的旧路径引用。

## 说明结果查找方法

在models/和runs/下的README.md中分别说明各个工程的使用方法，包括结果查找方法。查找方法应该放在工程文件夹里面的README.md，而非脚本文件夹里。打开哪个工程看图要说清楚。工程文件夹里的README.md按这样的结构编写：以工程名为小标题，每个小标题下再来几个小标题：工程打开后使用方法、可以得到的结果（如截图）。脚本文件夹里的README.md按这样的结构编写：以脚本名为小标题，每个小标题下再来几个小标题：脚本用途、使用方法。
