# 仿真工作流程

## 查找算例

工作目录为 `D:\SRTP_Work`。先读根目录 `AGENTS.md` 和目标案例的 `README.md`，再查看相关 `models/`、`config/`、`scripts/` 和 `results/`。`models/source/` 存交接原件，`models/baseline/` 存固定输入基准，`results/runs/` 存原生运行工程。案例脚本留在案例的 `scripts/`，配置留在 `config/`。

## 交付脚本并执行

在案例 `scripts/README.md` 中用表格说明脚本的输入工程、配置、参数来源、功能、运行命令、原生输出位置和校验点；生成脚本时也用简表向用户说明。案例根 README 只保留目录和成功成果索引。输入参数来自用户给定条件、已核实的文献数值或配置文件，避免预设结果。脚本终端只显示状态、错误和路径；数值及分布在 Lumerical 原生工程中查看。除非用户当次明确要求，不额外制作结果表格或图片。

按根目录 `AGENTS.md` 中当前授权执行仿真脚本，检查退出状态、求解日志和原生结果；失败时定位首个具体错误并修正，避免重复无意义的长时间运行。给每次新运行使用独立目录，避免覆盖成功工程。

## 核验成果

先查脚本状态和求解器日志，再查原生工程中的结果名称、扫描点和监视器数据；用户提供截图后，按 `result-verification` skill 核对属性、偏压、坐标和色标。告诉用户具体到哪个路径、哪个工程、哪个对象和属性查看。只把成功且可用的脚本和工程写入案例 README；无须编写进度文档或失败经过。运行目录使用 `sNN_简短英文用途_YYYYMMDD_HHMMSS`。不得仅凭 `SIM_DONE_STATUS=0` 认定物理结果正确。日志判读细节见 [references/log-error-patterns.md](references/log-error-patterns.md)。

## 说明结果查找方法

在 `models/` 和每个成功的 `results/runs/<算例>/` 下的 README.md 中逐工程说明。以工程文件名为小标题，其下依次并列写 `算例做了什么`、`工程打开后使用方法`、`可以得到的结果（及截图）`。第一节简述输入工程、改变的参数或结构、仿真目的及范围；对未完成或未核验的结果明确标注，不能把计划写成成果。第二节写清楚打开哪个原生工程以及软件中的操作入口。第三节列出工程内结果对象、属性、偏压或波长范围、截图路径和核验重点。一个算例有多个工程时逐一说明，并用简表概括各工程分工。结果查找方法放在工程目录的 README.md；脚本目录的 README.md 仍以脚本名为小标题，说明脚本用途和使用方法。
